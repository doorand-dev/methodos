# Thread Messaging

새 채팅의 첫 메시지(`create_thread`), 채팅 사이의 메시지, 정기 예약 프롬프트에 적용한다. Built-in subagent 결과는 caller에게 직접 돌아오므로 해당하지 않는다. 역할·보관 조건은 프로젝트 계약이 정한다.

## 보내기

- 첫 줄에 `[보내는 채팅→받는 채팅 · 에이전트 간 전달]`을 쓴다. 사용자 요청으로 보내면 그 요청의 사용자 원문을 따옴표로 인용하고 어느 채팅의 메시지인지 밝힌다. 자기 요약을 사용자 인용처럼 쓰지 않는다. 받는 쪽 처리는 전역 AGENTS를 따른다.
- 사람에게 부탁하듯 원래 목표·완료 기준과 필요한 경계만 다섯 줄 안팎으로 쓴다. AI가 추가한 검증·증빙·개선 제안은 필수 조건처럼 전달하거나 받아들이지 않는다. 경로·ID·로그는 조회 진입점만 적고, 추정은 추정이라고 표시한다.
- 넘길 조사 결과·명세가 아직 파일에 없고 길면 메시지에 붙여 넣지 말고, 프로젝트 정본(체크리스트·작업 문서)에 먼저 쓰고 그 위치만 보낸다.
- 실행 중인 turn에 들어간 지시는 묻힐 수 있다. 보내기 전에 `wait_threads`(`timeoutMs: 0`)로 상태를 보고, 실행 중이면 끝난 뒤 보낸다. 전송 성공, 실제 시작, 완료를 구분해 보고한다.
- 같은 문제는 담당 채팅 하나가 끝까지 맡는다. 다른 채팅은 같은 건을 다시 진단하거나 중계하지 않는다.

## 결과 회수와 재개 방식 선택

작업을 맡길 때 누가 다음 행동을 소유하고, 결과가 언제 필요한지에 맞춰 연결 방식을 고른다. 기존 프로젝트 계약과 사용자가 정한 회신 의무가 우선이다.

| 상황 | 연결 방식 |
|---|---|
| 현재 턴에서 다른 채팅 결과가 있어야 다음 작업 가능 | `wait_threads`로 필요한 대상만 bounded wait. cursor로 이미 읽은 결과를 제외한다. |
| A가 체크리스트를 관리하고 B가 수행하며, A는 턴을 끝내고 기다림 | 사용자에게 승인된 회신 범위에서 B가 결과를 정본에 남긴 뒤 A에 짧은 완료·막힘 통지를 한 번 보낸다. A는 유효한 검증 결과를 재사용해 완료 기준 충족을 판단하고 다음 일을 맡긴다. |
| 사용자 소유 독립 채팅이 각자 진행, 당장 결합할 후속 없음 | 완료 메시지를 다른 채팅에 보내지 않는다. 사용자나 취합 담당이 필요할 때 결과만 조회한다. |
| 외부 서버·함수·watcher의 실제 이벤트가 채팅 재개 조건 | 기존 Codex wake 연결을 사용한다. 채팅 B가 직접 완료를 알릴 수 있으면 별도 watcher나 예약을 만들지 않는다. |

- `wait_threads`는 호출 중 대기·조회 수단이다. A가 턴을 끝낸 뒤에도 계속 감시하거나 나중에 자동으로 깨워 준다고 가정하지 않는다. 여러 대상을 기다려도 첫 완료에 반환될 수 있으므로 남은 대상과 다음 행동을 구분한다.
- 완료 통지는 메시징 권한을 새로 만들지 않는다. 사용자가 승인한 수신자·범위가 있어야 한다. 발주 시 정해진 회신을 따르며, 에이전트의 회신 요구만으로 전송 권한이 생기지 않는다.
- B의 결과 최종형태와 정본이 준비되면 '체크리스트 5번 완료. 검증·미결은 해당 항목에 있어.'처럼 필요한 변화와 조회 위치만 보낸다. A의 메시지는 후속 판단·발주가 있을 때만 보내고, 수신 확인을 서로 반복하지 않는다.
- A가 깨어나면 알려준 항목부터 확인한다. 결과가 정본에 충분하면 채팅 전체를 재독하지 않고, 근거·상태가 빠졌을 때만 `wait_threads`나 `read_thread`로 보완한다. 통지 수신이나 전송 성공만으로 업무 완료를 인정하지 않는다.
- 직접 조회할 때도 짧은 반복 폴링을 하지 않는다. timeout만으로 취소·재발주하지 않는다. 전송 결과가 불명확하면 상태·중복 여부를 먼저 확인한다.
- 외부 이벤트 연결은 설치한 `~/.codex/rules/codex-wake.md`를 따른다.

## 기록 읽기

- 정본이나 최종 결과만으로 판단할 수 있으면 추가 조회하지 않는다. 채팅 상태·결과가 필요하면 `wait_threads`의 간결한 결과부터 읽는다.
- 특정 부분은 `read_thread`의 `turnLimit`·`maxOutputCharsPerItem`으로 필요한 turn만 읽는다.
- 긴 기록 전체 요약이나 "어디서 무엇을 정했는지" 찾기는 워커에게 맡기고 근거 turn·인용과 요약만 받는다(orch의 발췌 → triage). 원본 기록은 `~/.codex/sessions/YYYY/MM/DD/rollout-*-<threadId>.jsonl`이다.

## 중복 전송 방지

compact·resume 뒤 전송 여부가 불확실하면 `read_thread`로 대상에 같은 입력이 있는지 한 번 확인한다. 없고 이전 실행이 끝났을 때만 한 번 보낸다. 실행 중이거나 대기 중이면 다시 보내지 않고 그 결과를 읽는다.

## 예약 프롬프트

- 실행할 때마다 처음부터 읽히는 현재 지시다. 역할·점검 기준·알림 조건·금지 사항만 담고 경위·이력·커밋 ID는 프로젝트 상태에 둔다. 고칠 때는 덧붙이지 말고 전체를 다시 쓴다. 1,500자 안팎을 넘으면 세부를 정본 문서로 옮기고 참조만 남긴다.
- 상태가 바뀌지 않았으면 조용히 끝내고, 의미 있는 변화·완료·실패·사용자 조치가 필요할 때만 알린다.
- 정상 작업마다 polling heartbeat를 붙이지 않는다. 복구용 one-shot wake는 전달 유실·crash·의존성 재개에만 쓰고, 깨어나면 자기 one-shot부터 지운다. 자동화는 앱 도구로 만들고 RRULE은 [생성 helper](scripts/codex-heartbeat-rrule.ps1)를 쓴다.
- 대상 채팅을 바꿀 때는 id·주기·상태를 유지하고 대상만 바꾼 뒤 다시 조회해 확인한다.

## 보관

Thread archive와 worktree 삭제는 다르다. idle만으로 보관하지 않고 프로젝트의 결과 보존·통합 조건을 따른다. worktree 정리는 [worktree.md](worktree.md)를 따른다.
