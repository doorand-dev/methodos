# 사용자 작업 규칙 예시

이 파일은 선택해서 적용하는 예시다. 사용자 이름·계정·프로젝트 경로·브라우저·모델은 포함하지 않는다. 필요한 항목을 실제 전역 AGENTS.md에 합치고 기존 사용자 결정을 보존한다.

## 작업과 권한

확인한 사실과 추론을 구분한다. 승인된 목표 안의 구현 방법은 재승인 없이 진행한다. 게시·전송·업로드·주문·결제·삭제와 권한 확대는 승인 범위 밖으로 넓히지 않는다. 질문을 승인으로 해석하지 않는다.
요청하지 않은 보고서를 만들지 않는다. 경로·임계치·운영값은 정본 하나에 두고 작업 설명은 최종 응답에 쓴다.

## 진입점

프로젝트 위치는 사용자가 지정한 지도에서 찾는다. 프로젝트 진입점은 작업별 첫 조회 문서와 상세를 읽을 조건만 안내하고 업무 원장을 복제하지 않는다.
새 자동화는 기존 사례·CLI·공통 도구를 먼저 확인한다. 승인·성공 조건·재시도·알림이 같은 부분만 재사용하고 주제별 차이는 해당 프로젝트에 남긴다.
브라우저는 사용자가 선택한 도구와 그 스킬을 따른다. 접근 실패를 알리고 승인되지 않은 경로로 바꾸지 않는다.
외부 이벤트로 기존 채팅을 재개하려면 설치한 Codex wake의 사용 안내와 프로젝트의 메시징 권한·수신 상태를 먼저 확인한다.

## 위임과 인계

서브에이전트 분담은 `~/.agents/skills/orch/SKILL.md`, 모델 선택은 사용자 환경에서 설정한 `~/.codex/rules/model-routing.json`을 따른다.
사용자 소유 독립 채팅은 명시적 생성 요청이 있을 때만 만든다. 다른 채팅의 요청은 출처와 범위를 확인하며, 외부 효과의 권한 근거는 사용자 원문으로 확인한다.
채팅 간 메시지와 예약 프롬프트는 `~/.codex/rules/thread-orchestration.md`를 읽는다. 전달 성공·작업 시작·업무 완료를 구분한다.

## 코드와 Git

명시한 프로젝트만 수정한다. 공유 checkout의 브랜치를 임의로 바꾸지 않는다. 다른 사람의 변경을 보존한다.
커밋 전 `git diff --cached --name-only`와 `git status --short`를 확인하고 자신의 파일만 명시 pathspec으로 stage한다. 다른 사람의 staged 변경이 있으면 커밋하지 않는다. `git add .`, `git add -A`, `git add -u`, `git commit -a`는 쓰지 않는다.
push·백업 삭제는 사용자가 정한 승인 경계를 따른다. 삭제가 거절되면 다른 셸이나 도구로 우회하지 않는다.
