# Finding

확인된 외부 동작·실패·우회법·재현조건을 소유 프로젝트의 기존 기록에 간결하게 남긴다.
막힘이 없는 발견도 기록할 수 있다. 사실과 추론을 구분해 다음 작업에서 같은 조사를 반복하지 않게 한다.

## 호출과 범위

- `finding`, `/finding`, “이거 발견 기록해”, “발견 남겨”처럼 기록을 요청하면 수행한다.
- 대화에서 발견을 감지했을 뿐이면 기록을 제안만 한다. 이미 기록을 요청받았다면 재승인을 요구하지 않는다.
- “X 관련 발견 있어?”는 기존 기록 검색으로 처리한다.
- 선택 이유와 tradeoff는 기존 의사결정 기록에, 미완료 작업은 기존 체크리스트·이슈·작업 원장에 둔다. 발견 기록을 위해 별도 작업 관리 절차를 만들지 않는다.

## 기록 위치와 내용

먼저 프로젝트가 지정한 기록 위치와 같은 주제의 기존 기록을 확인한다. 해당 기록에 추가하거나
프로젝트 형식에 맞춰 작성한다. 별도 지정이나 적절한 기록이 없으면 `docs/findings/`를 쓰며,
`docs/`가 없는 프로젝트에서는 기존 `findings/`도 사용할 수 있다. 파일별 기록이나 번호 할당을
전역 요건으로 강제하지 않는다.

결론을 앞에 쓰고, 다시 판단하거나 재현하는 데 필요한 내용만 덧붙인다:

- 실제 확인한 동작, 실패한 시도 또는 작동한 우회법
- 결과에 영향을 준 환경·입력·버전·권한 등 재현조건
- 시간이 지나면 달라질 사실의 확인 날짜, 로그·명령·코드 위치·URL 등 필요한 근거
- 아직 확인하지 않은 조건이나 추정이 있다면 그 한계

빈 항목을 채우거나 고정 양식을 맞추려고 내용을 만들지 않는다. 실패 원인을 확인하지 못했으면
관찰된 실패와 원인 추정을 분리한다. 비밀값은 기록하지 않고 필요한 경우 위치만 가리킨다.

## 기존 기록과 검색 호환

기존 `docs/findings/` 기록의 파일명·번호·태그·링크를 보존한다. 이 스킬 정비를 이유로
일괄 이동·이름 변경·삭제하지 않는다. 관련 내용을 찾을 때 기존 태그와 일반 검색어를 함께 쓴다.
예를 들어 해당 폴더가 있으면 `rg -n -F '[태그]' docs/findings/` 또는
`rg -n '검색어' docs/findings/`로 찾고, 프로젝트가 지정한 다른 기록 위치도 검색한다.

사실이 바뀌면 확인한 날짜와 새 근거를 덧붙이거나 후속 기록으로 연결해 과거 조건과 현재 조건을
구분한다. 미확인 상태를 최신 사실로 단정하지 않는다. 모든 기록의 영구보존을 강제하지 않으며,
보존·정리는 프로젝트 규약과 사용자 승인 범위를 따른다.

기존 `<workspace>/.Codex/finding.toml`이 있으면 `root_override`(기록 위치)와
`extra_triggers`(제안할 발견 발화)를 참고한다. 이 설정을 새로 만들 필요는 없다.

## 전역 재사용 경계

프로젝트 근거는 소유 프로젝트에 둔다. 전역 지식에서 재사용할 때는 원본 링크로 연결하며,
이 스킬 호출만으로 ai-knowledge나 다른 프로젝트의 기록을 읽거나 바꾸지 않는다.
