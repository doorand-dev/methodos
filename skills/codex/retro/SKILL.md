# 세션 돌아보고 개선하기

사용자가 원인을 먼저 분류할 필요 없이 실제 세션에서 반복 개입·재작업·불필요한 도구 사용을 찾아 줄인다.

- 지정한 세션의 관련 대화·실행 결과와 현재 구현을 대조한다. 지정하지 않으면 현재 세션을 본다. 다른 채팅은 읽기만 하며 메시지·작업 지시를 보내지 않는다. 기록에 접근할 수 없으면 확인 범위를 밝히고 원인을 만들어내지 않는다.
- 같은 정보를 다시 찾기, 새 근거 없는 재시도, 불필요한 전체 재실행, 과한 출력·검증, 사용자가 반복 보완한 누락 중 실제 발생한 비용을 찾는다. 필요한 탐색·변경된 요구·정상 실패를 낭비로 단정하지 않는다. 측정하지 않은 절감 수치는 만들지 않는다.
- 원인이 문맥·코드·도구 선택·재사용 기능 부재 중 어디에 있는지 증거로 판단한다. 같은 원인은 묶고, 무변경·삭제·기존 경로 수정·실제 반복 기능 공통화 중 작은 해법을 선택한다. 회고할 때마다 규칙·훅·테스트·새 문서를 늘리지 않는다.
- 개선까지 요청하면 승인된 경로·작업 범위에서 수정하고 해당 낭비나 실패를 줄였는지 최소 확인한다. 회고·분석만 요청하면 근거와 권고에서 끝낸다. 다른 프로젝트·외부 효과·권한 변경은 임의로 확장하지 않는다.

결과는 실제 낭비와 원인, 반영한 개선 또는 무변경 이유, 확인 범위와 미해결 사항을 짧게 전달한다. 별도 회고 저장소·의무 보고서·검수자·스킬 실행 순서를 만들지 않는다. 기존 관련 사건 기록이 있으면 처리 결과를 갱신하며 원문 기록은 보존한다.

“방금 이 실수”는 [blame-context](../blame-context/SKILL.md)의 좁은 사건 진단으로 처리할 수 있다. 문맥 정리·구조 개선은 [improve-context](../improve-context/SKILL.md), 반복 실행 공통화는 [workflow-reuse](../workflow-reuse/SKILL.md)의 기준을 필요할 때만 참고한다. 이 연결은 사용자에게 원인 분류나 추가 호출을 요구하는 단계가 아니다.
