# 단계 AI 입력 감사

서버·스크립트가 모델에 직접 보내는 프롬프트·첨부·출력 schema를 감사할 때 읽는다.

- 근거 순서: 호출별 실제 전송 기록(입력 목록·절·해시·글자 수) → 입력을 조립하는 코드 → 원본 문서. 전송 기록이 없으면 조립 코드를 따라가되 결론에 "전송 기록 없음"을 남긴다.
- 판단 기준과 실제 예시가 빠졌는지 본다. 입력 축소 변경 전후의 같은 단계 출력을 비교하며, 크기 감소를 개선 근거로 쓰지 않는다. 기준만 남고 실제 예시가 빠지면 출력 품질이 먼저 떨어진다.
- 같은 지침·원문이 여러 단계에 반복 전송되는지, 판단과 무관한 운영 절차·경위·권한 설명이 들어가는지 본다.
- 보정·재시도 호출이 실패한 필드와 실패 사유만 보내는지, 이전 응답 전체를 다시 보내고 전체 출력을 다시 받는지 본다.
- 출력 schema가 이미 확정된 값을 다시 출력하게 하거나 원문을 그대로 베끼게 해 문자열 대조 실패를 만드는지 본다. 원문은 식별자로 고르게 하고 본문은 코드가 붙이는 편이 맞다.
- 실제 호출의 모델·effort가 현재 설정과 같은지 사용량 기록으로 확인한다. 상위 실행의 설정을 단계 호출의 값으로 간주하지 않는다.
- 큰 원자료(전사·원문)는 그 자체로 결함이 아니다. 판단에 쓰이는지와 매 호출 반복되는지로 판단한다.
- 수정은 조립 코드나 프롬프트 정본 한 곳에서 하고, 같은 입력을 쓰는 다른 단계·채널 소비자도 확인한다.
