# 컨텍스트 정리·개선

사용자는 청소와 재설계를 미리 구분할 필요가 없다. 실제 AI가 읽고 판단하는 경로를 조사해 유지·삭제·국소 수정·구조 변경 중 가장 작은 유효 해법을 적용한다.

- 요청 범위의 진입점에서 정본·작업 상태까지 따라간다. 누가 언제 무엇을 읽고 갱신하는지, 우선순위·권한·만료·누락·충돌 처리가 실제 환경과 맞는지 확인한다. 신규 세션·인계·압축이 같은 입력을 받는다고 가정하지 않는다.
- `.Codex/context-friction.md`가 있으면 반복 원인·미해결·재발을 현재 경로와 대조한다. 기록은 단서이며 기록된 항목만 감사하지 않는다. 파일의 존재나 상호 참조만으로 필요성을 인정하지 않는다.
- 중복 정본, 끝난 작업의 임시 절차, 끊긴 참조, 쉽게 조회 가능한 환경 값의 복제부터 정리한다. 모델의 기본 행동을 반복 지시하는 문장은 실제 사용 근거로 삭제를 판단한다. 권한·작업 고유 제약은 보존하며 불확실한 후보는 근거와 함께 남긴다.
- 모든 작업에 필요한 내용만 상시 입력에 두고, 특정 경우의 세부 내용은 읽을 조건이 분명한 참조로 옮긴다. 같은 개념의 정의·규칙·예외는 함께 둔다. 필요한 정보를 숨기거나 판단 부담을 다른 AI에게 옮기는 분리는 피한다.
- 반복 상태는 실제 조회 결과에서 종료 항목·만료 후보·이미 처리한 후보와 긴 증거가 계속 들어오는지 본다. 보존 필요성과 매회 읽을 필요성을 구분하고, 미완료·불확실·후속 처리 대기 및 최소 중복 방지 기록을 잃지 않게 조회를 고친다. 구조화 데이터의 크기·증가량은 후보 신호이며 정상 원자료도 크므로 크기만으로 분리·삭제하지 않는다. 큰 JSON을 발견하면 본문 전체부터 읽지 말고 메타데이터·필드 구성·실제 소비자를 먼저 확인한다.
- 배치가 반복 탐색·판단의 원인이면 요청 범위에서 구조도 개선한다. 새 계층을 없앴을 때 어떤 실제 독자에게 어떤 부담이 돌아오는지 비교하고, 기존 구조나 국소 수정으로 충분하면 거기서 끝낸다. 옛 소비 경로·이중 정본을 정리하고 필요한 상태 이전과 복구 방법을 고려한다. 자동 동작은 실제 실행 주체와 계기가 있어야 한다.
- 변경한 입력·참조로 다음 AI의 목표·권한·현재 상태·첫 행동이 분명한지 최소 확인한다. 조회를 바꿨으면 종료 이력이 쌓인 대표 상태에서 실제 출력과 필요한 항목의 보존을 전후 비교한다. 파일 수·본문 길이 감소를 효과로 대신하지 않는다. 관련 사건의 상태와 처리 결과를 갱신한다. 새 주기 점검은 요청된 범위에서만 연결하며 규칙·훅·보고 단계 추가를 기본 해법으로 삼지 않는다.

일반적인 정리·개선 요청은 해당 범위의 수정과 검증까지 포함한다. 감사만·제안만·읽기 전용 요청은 거기서 끝낸다. 사용자 동작·권한·외부 효과나 다른 프로젝트로 범위를 넓히는 선택은 별도로 다룬다.

## AI 입력 표면별 기준

특정 AI 입력을 감사할 때는 아래에서 해당하는 기준 하나만 읽는다. 여러 표면을 함께 맡았을 때만 해당 기준을 각각 읽는다. 공통으로, 원본 문서보다 실제로 전달된 입력과 그 결과(받은 AI의 첫 행동·출력)를 먼저 본다. 전달 기록이 없으면 없다고 밝히고, 원본 문서만으로 무엇이 들어갔는지 단정하지 않는다.

| 표면 | 기준 |
|---|---|
| 서버·스크립트가 모델에 보내는 단계 입력 | [stage-inputs](references/stage-inputs.md) |
| 정기 예약(automation) 프롬프트 | [scheduled-prompts](references/scheduled-prompts.md) |
| 서버·watcher가 채팅을 깨우는 알림 | [server-wakes](references/server-wakes.md) |
| 채팅 간 메시지 | [thread-messages](references/thread-messages.md) |
| handoff·인계 JSON | [handoffs](references/handoffs.md) |
| AGENTS·스킬·운영 문서 | 이 파일의 위 기준 |

구조 변경은 [HTML 보고서](../improve-codebase-architecture/HTML-REPORT.md)로 실제 전후 경로·줄어드는 반복 판단·남는 비용을 보여준다. 단순 수정은 짧게 보고하고 HTML을 중간 승인 관문으로 만들지 않는다. 의무 스킬 연쇄·고정 후보 수·전체 회귀·독립 검수를 붙이지 않는다.

로딩·압축·memory 동작이 쟁점일 때만 [수명 참고](references/codex-context-lifetimes.md)를 읽는다. 특정 다음 AI의 시작 입력 검토는 [context-novelist](../context-novelist/SKILL.md), 방금 발생한 사건은 [blame-context](../blame-context/SKILL.md), 세션에서 어디가 낭비였는지부터 찾는 일은 [retro](../retro/SKILL.md)와 구분한다. 이미 확인한 문제를 이 링크로 다시 발주하지 않는다.
