# 구조 변경 HTML 보고서

세 스킬에서 구조의 전후 차이를 사용자에게 설명할 때 읽는다. 단순 값·참조의 국소 수정은 생략할 수 있다. 요청이 제안이면 대안을, 구현까지 맡겼으면 반영 결과를 보여주며 보고서 작성 때문에 재승인을 기다리지 않는다.

- 기존 사용자 지정 출력 위치가 없으면 OS 임시 디렉터리에 고유한 이름의 단일 HTML을 만든다. 한국어 설명과 내장 CSS·SVG로 네트워크 없이 핵심 내용이 보이게 한다. 가능한 Codex 파일 패널로 열고 최종 응답에 절대 경로를 연결한다.
- 핵심은 전후 그림과 구체적인 근거다. 실제 확인한 현재 상태·제안·반영 완료를 구분한다. 관련 파일·진입점, 줄어드는 부담, 남는 비용·불확실성과 권고를 필요한 만큼 담는다. 후보 수·카드 수·색상·도구·별도 보고서 스킬을 강제하지 않는다.
- 코드 구조: 호출 관계와 호출자가 알아야 하는 사실, 모듈 내부가 맡게 되는 책임을 비교한다.
- 컨텍스트 구조: 실제 AI 진입점에서 정본·작업 상태로 이어지는 경로, 항상 읽는 내용과 조건부 참조, 중복·충돌·만료 처리를 비교한다.
- 반복 작업: 전용 코드·수동 연결이 공통 실행으로 바뀌는 흐름, 작업별 입력과 AI 판단 지점, 해당되는 경우 재개 경계를 보여준다.
- 토큰·시간·비용 절감은 측정한 경우에만 수치로 표시하고 측정 범위를 밝힌다. 구조상 기대 효과를 실측 성과로 쓰지 않는다. 시각 면적이나 파일 수를 개선 점수로 삼지 않는다.

보고서는 설명 도구다. 새로운 승인 단계·고정 질문 순서·전체 회귀·의무 독립 검수를 만들지 않는다.
