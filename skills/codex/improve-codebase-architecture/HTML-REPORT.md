# 구조 변경 HTML 보고서

구조의 전후 차이를 HTML로 설명할 때 공유하는 품질 기준이다. HTML 작성 여부는 호출한 스킬과 사용자 요청이 정하며, 이 문서를 참조한다고 HTML이 의무가 되지는 않는다. 단순 값·참조의 국소 수정은 생략할 수 있다. 요청이 제안이면 대안을, 구현까지 맡겼으면 반영 결과를 보여주며 보고서 작성 때문에 재승인을 기다리지 않는다.

- 기존 사용자 지정 출력 위치가 없으면 OS 임시 디렉터리에 고유한 이름의 단일 HTML을 만든다. 한국어 설명과 내장 CSS·SVG로 네트워크 없이 핵심 내용이 보이게 한다. 가능한 Codex 파일 패널로 열고 최종 응답에 절대 경로를 연결한다.
- 핵심은 전후 그림과 구체적인 근거다. 실제 확인한 현재 상태·제안·반영 완료를 구분한다. 관련 파일·진입점, 줄어드는 부담, 남는 비용·불확실성과 권고를 필요한 만큼 담는다. 후보 수·카드 수·색상·도구·별도 보고서 스킬을 강제하지 않는다.
- 코드 구조: 호출 관계와 호출자가 알아야 하는 사실, 모듈 내부가 맡게 되는 책임을 비교한다.
- 컨텍스트 구조: 실제 AI 진입점에서 정본·작업 상태로 이어지는 경로, 항상 읽는 내용과 조건부 참조, 중복·충돌·만료 처리를 비교한다.
- 반복 작업: 전용 코드·수동 연결이 공통 실행으로 바뀌는 흐름, 작업별 입력과 AI 판단 지점, 해당되는 경우 재개 경계를 보여준다.
- 토큰·시간·비용 절감은 측정한 경우에만 수치로 표시하고 측정 범위를 밝힌다. 구조상 기대 효과를 실측 성과로 쓰지 않는다. 시각 면적이나 파일 수를 개선 점수로 삼지 않는다.

보고서는 설명 도구다. 새로운 승인 단계·고정 질문 순서·전체 회귀·의무 독립 검수를 만들지 않는다.

## 시각적 완성도와 확인

- 첫 화면에서 핵심 문제와 제안·반영 결과를 파악할 수 있게 정보 위계를 잡는다. 제목·요약·전후 비교·근거 상세를 구분하고, 본문을 동일한 카드 여러 개에 옮기는 것으로 설계를 대신하지 않는다.
- 전후 도식은 같은 범위·명칭·방향으로 비교한다. 색·선·그룹의 의미를 일관되게 쓰고 필요하면 범례를 둔다. 무엇이 이동·통합·제거됐고 어떤 책임이 남았는지 구체적인 진입점·호출부로 표시한다. 색만으로 차이를 전달하지 않는다.
- 읽기 쉬운 글자 크기·대비·여백과 제한된 강조색을 사용한다. 긴 경로·설명이 도식의 선이나 레이블과 겹치지 않도록 배치하고, 좁은 화면에서도 읽을 수 있게 재배치하거나 명시적인 스크롤 영역을 제공한다.
- 요약의 각 주장을 실제 파일·입력·관찰 근거와 연결한다. 상세는 필요할 때 펼칠 수 있지만 핵심 비교와 미확인 사항을 숨기지 않는다. 불필요한 차트·애니메이션·상호작용을 추가하지 않는다.
- 작성 후 사용자 환경의 지정 브라우저로 실제 렌더와 스크린샷을 확인한다. 주요 화면 폭에서 도식·글자의 잘림·겹침과 대비, 추가한 링크·펼침 동작을 확인하고 고친다. 렌더를 확인하지 못하면 오류와 미확인 범위를 밝히며, 파일 생성 성공을 시각 검증으로 대신하지 않는다.
