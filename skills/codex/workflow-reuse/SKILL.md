# Workflow Reuse

개별 작업에서 확인한 실행 방법을 프로젝트의 재사용 가능한 기능으로 옮긴다. 이후 AI는 작업별 입력과 의미 판단을 담당하고, 반복 실행은 기존 공통 코드를 호출하게 한다.

- 실제 작업 흐름과 기존 함수·CLI·API·저장 상태를 먼저 확인한다. 반복되는 실행, 작업마다 달라지는 데이터, AI가 판단할 내용을 구분한다. ID·경로·문구·시간값 같은 작업별 하드코딩은 입력이나 기존 작업 데이터로 옮기고, 의미 판단을 임의 규칙으로 고정하지 않는다.
- 기존 실행 경로를 우선 확장한다. 현재 작업과 실제로 예정된 다음 작업에 필요한 차이만 수용하며, 가상의 모든 작업을 위한 엔진·플러그인·설정 체계를 만들지 않는다. 단순 입력화로 충분하면 거기서 끝낸다.
- 비용이 큰 재실행이나 외부 효과가 있는 단계는 기존 저장소에 필요한 처리 결과·입력 버전·진행 상태를 남겨 중복 실행과 실패 후 재개를 지원한다. 입력이 달라지면 영향받는 결과만 무효화한다. 간단한 함수에도 상태 저장·캐시·잠금 체계를 일괄 추가하지 않는다.
- 반복 상태의 보존량이 매회 AI 입력량이 되지 않게 한다. 현재 작업 목록과 처리 직전의 상세·중복 조회를 기존 진입점에서 호출하도록 연결하고, 종료·만료 항목이 일상 목록에서 빠지는 조건을 정한다. 불확실 결과와 후속 처리 대기를 완료로 치지 않으며 상세 증거는 필요할 때 다시 찾을 수 있게 둔다. 이를 위해 파일 분리나 별도 DB가 항상 필요한 것은 아니다.
- 기존 운영 진입점·호출부를 공통 기능에 연결하고 대체된 전용 스크립트와 참조를 정리한다. 예약 채팅에는 호출 조건·입력·AI 판단 지점만 남긴다. 공통화 요청으로 새 예약·배포·발송 권한이 생기지는 않는다.
- 바뀐 부분만 최소 검증한다. 기존 작업과 다음 작업의 실제 또는 대표 입력이 같은 경로를 쓰는지 확인하고, 중복·재개 동작을 바꿨을 때만 해당 실패 지점을 확인한다. 실제 외부 실행이 없었다면 dry-run 범위를 밝힌다. 전체 회귀·고정 테스트 수·의무 reviewer·검증 증명용 별도 보고서를 추가하지 않는다.

구조 변경은 [HTML 보고서](../improve-codebase-architecture/HTML-REPORT.md)로 전용 코드·수동 연결의 전후 흐름, 공통 실행·작업별 입력·AI 판단의 분담을 보여준다. 단순 입력화는 짧은 설명으로 충분하다. 구현까지 맡겼으면 반영 결과를 보여주며 보고서를 중간 승인 관문으로 삼지 않는다.

완료는 공통 함수의 존재가 아니라 다음 작업이 전용 코드를 다시 작성하지 않고 실제 진입점에서 그 기능을 사용할 수 있는 상태다. 재사용할 부분·작업별 입력·AI가 남겨 맡을 판단·확인한 범위를 짧게 보고한다. 평상시 반복 실행에서는 이 설계 작업을 다시 하지 않고 공통 기능을 사용한다.
