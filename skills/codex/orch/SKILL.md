# Orch

현재 채팅의 owner가 역할 배치를 하나 고르고, 필요한 패턴을 조합한다. 모델·effort와 워커 프로필은 사용자의 선호 정책인 `~/.codex/rules/model-routing.json`을 따른다. 이 파일은 프록시의 모델 전달·가용 목록을 대체하지 않으며, 실제 지원과 사용자 요청이 우선이다. 프로젝트 계약이 역할 구조를 따로 정하면 그것을 따른다.

## 역할 배치

| 배치 | 고르는 때 | 부모가 하는 일 |
|---|---|---|
| 직접 수행 | 작거나 순서대로 해야 하는 일, 다음 행동이 그 결과에 바로 묶인 일 | 전부 |
| 부모·워커 분담 | 서로 기다릴 필요 없는 일이 몇 개 있을 때 | 다음 단계를 막는 일은 직접 하고 곁가지를 위임 |
| 조정자·완결형 워커 | 큰 취합·여러 묶음 처리처럼 원문이 부모 컨텍스트를 채우면 안 되는 일 | 분해·배정·쟁점 판단·통합. 원문을 다시 읽지 않음 |

## 조합 패턴

- **발췌 → triage → 심층 처리:** 자료가 많고 필요한 것은 일부일 때. 도구나 고속 등급으로 발췌하고, 워커가 관련성·중복·충돌·판독 실패를 분류한 뒤 필요한 항목만 후속 처리한다. 제외 이유, 채택한 핵심 수치·주장의 원문 위치, 추출 실패, 충돌한 값을 다음 담당에게 넘긴다.
- **단계 인계:** 추출·판단·작성처럼 성격이 다를 때 앞 단계의 확정 산출물만 넘긴다.
- **예외 상신:** 기준으로 처리되는 건 워커가 끝내고 충돌·미확인·기준 밖 항목만 부모에게 올린다.
- **독립 검토:** 배포·실거래·외부 게시 전이나 구체적 위험이 있을 때. 작성자와 다른 워커가 하고, 중요한 결정은 다른 제공자 모델로 한다. 근거 있는 지적만 반영한다.

독립 검토가 필요한 변경은 요구사항 충족과 프로젝트 기준·구현 품질을 구분해 발주하고 결과에도 구분을 남긴다. 두 관점을 독립적으로 확인할 이득이 있을 때만 워커를 나눈다. 검토할 변경 범위와 비교 기준을 고정하고, 미커밋 변경도 대상이면 포함한다. 요구사항 근거는 사용자 요청·확정된 동작·명세에서 찾고, 없는 부분은 미확인으로 남긴다. 한 관점의 통과로 다른 관점까지 통과했다고 판단하지 않는다.

## 발주

워커에게 목표, 담당 범위와 쓰기 가능한 경로, 기대 산출물과 완료 기준, 필요한 최소 문맥만 준다(`fork_context=false`). 병렬 편집은 쓰기 범위를 나누고, 겹치면 worktree로 격리한다(`~/.codex/rules/worktree.md`). 부모와 워커가 같은 일을 하지 않는다.
`aside exec` 같은 외부 에이전트도 워커 한 명으로 센다. 서브에이전트에게 다시 외부 에이전트에 맡기라고 하지 않는다. 이중 위임이 되기 때문이다. 단순 확인을 여러 묶음으로 나눌 때는 부모가 외부 에이전트나 서브에이전트 중 한 층만 써서 병렬로 맡긴다.

## 진행과 새 자료

위임한 뒤 부모는 겹치지 않는 일을 한다. 사용자 소유 별도 채팅과 장기 협업할 때는 `~/.codex/rules/thread-orchestration.md`에 따라 현재 턴의 대기 조회, 승인된 완료 통지로 관리 채팅 재개, 독립 진행 중 하나를 고른다. 아래 `wait_agent`는 built-in subagent의 회수이며 별도 채팅의 재개 방식과 혼동하지 않는다. v1 built-in subagent의 완료 알림은 쉬고 있는 부모를 깨우지 않으므로, 결과가 필요하면 같은 턴에서 `wait_agent`로 받는다. 경과 시간만으로 취소·재발주하지 않는다.
기다릴 때는 결과가 필요한 시점에 수 분 단위로 한 번에 기다린다. 10초 간격 같은 반복 조회는 조회할 때마다 부모의 전체 문맥을 다시 읽는다. 부모 몫의 긴 명령도 백그라운드로 돌려 놓고 반복 조회하지 말고, 충분한 대기 시간으로 실행하거나 워커 대기와 한 번에 기다린다.
작업 중 최신 회신 같은 새 자료가 오면, 영향받는 결과의 담당 워커가 전체 대체인지 일부 수정인지 확인하고 갱신한다.

## 회수와 완료

워커 완료는 담당 산출물·검증 결과·미결을 제출한 것이다. 부모는 회신과 산출 문서 맨 위의 판단 요약만 읽고, 필요한 근거 위치만 확인한다.
전체 완료는 통합 담당(부모 또는 지정 워커)이 대상 누락, 최신본 교체, 본문·별첨 참조를 확인한 때다. 회수한 워커는 `close_agent`로 닫는다. 닫기 전까지 동시 실행 한도를 차지한다.
