# 독자의 질문에 답하는 글쓰기

독자가 무엇을 궁금해하고, 앞의 설명을 읽은 뒤 무엇을 이해하거나 판단해야 하는지부터 잡는다. 문장이 짧고 어미가 다양한지가 아니라 처음 읽어도 내용이 이어지는지를 본다. 필요한 설명과 예시는 충분히 쓴다.

## 작업의 크기에 맞춰 시작

- 짧은 글과 범위가 정해진 수정은 바로 작성한다. 별도 개요·모델 비교·검수 절차를 의무적으로 만들지 않는다.
- 긴 글은 전체 흐름을 먼저 파악한 뒤, 하나의 궁금증을 해결하는 섹션 단위로 쓴다. 문단마다 따로 생성해 도입·정리·주의사항을 반복시키지 않는다.
- 기존 글을 고칠 때는 유용한 설명과 목소리를 살린다. 표현을 붙잡고 어미만 바꾸는 수준에 머물면 독자의 질문과 앞뒤 문맥을 기준으로 해당 부분을 다시 설명한다. ‘고쳐 주세요’라는 요청 자체를 실패 원인으로 단정하지 않는다.

## 작성에 필요한 문맥

독자와 목적, 이번에 답할 질문, 앞에서 이미 설명한 것과 다음 주제, 필요한 원문·사실 자료를 사용한다. 표·도해가 있으면 그것이 이미 보여주는 내용도 확인한다. 짧은 글에 이 항목을 모두 채우게 하거나 사용자에게 이미 아는 내용을 다시 묻지 않는다.

사실의 근거와 문체 참고자료는 구분한다. 문체가 맞지 않으면 사용자가 선호한 짧은 예시를 참고하되, 그 예시의 체험·주장까지 가져오지 않는다. 조회·추천 수는 문체나 정보 정확성의 증거로 쓰지 않는다.

별도 작성자에게 맡길 때는 이번 부분에 필요한 문맥만 전달한다. 전체 대화, 실패한 문안 모음, 이 스킬 전문, 코드·배포 절차와 긴 금지 목록을 작성 프롬프트에 그대로 붙이지 않는다. 짧은 입력의 출발점은 다음 정도다. 필요한 항목만 쓴다.

```text
[독자]가 [목적]으로 읽는 글입니다.
이번에 궁금한 것: [...]
앞에서 다룬 내용 / 다음에 다룰 내용: [...]
이번 부분의 원문과 사실: [...]
표·도해가 보여주는 내용: [...]

이어 읽는 사람이 이해할 수 있도록 작성하세요.
원문의 유용한 설명은 살리고 필요한 설명과 예시는 충분히 쓰세요.
결과는 본문만 주세요.
```

## 설명의 순서와 내용

- 정의부터 나열하지 말고, 독자가 그 개념을 알아야 할 이유와 앞 문맥을 함께 본다. 모든 전문용어를 풀이할 필요는 없지만 다음 설명을 이해하거나 판단하는 데 필요한 개념은 남긴다.
- 설명 뒤에는 그 정보로 무엇을 비교·판단할 수 있는지 구체적으로 보여준다. 사양·기능을 나열하고 ‘선택이 쉬워집니다’로 맺는 대신 실제 차이·조건·예시를 쓴다.
- 질문은 앞 설명에서 자연스럽게 생길 때 쓴다. 모든 제목을 질문형으로 만들거나 문단마다 공감 도입·결론·행동 유도를 붙이지 않는다. 추천 글은 대상 독자의 선택 기준과 그 제품을 고를 이유가 드러나게 쓴다.
- 표·도해와 본문의 역할을 나눈다. 그림에 나온 숫자를 다시 열거하기보다 그 숫자의 의미나 판단에 미치는 영향을 설명한다. 본문만으로도 필요한 이해는 가능하게 한다.
- 역할·기여·범위는 사실에 맞게 전달한다. 특정 사례를 전체 경험처럼 넓히거나, 자연스러운 문체를 만들려고 없던 경험·효능·성과를 보태지 않는다.

## 검토는 실제로 막히는 곳에

초안을 이어 읽고 어디서 다시 읽게 되는지, 무엇이 빠졌거나 반복되는지 확인한다. 부족한 설명은 보완하고 오류는 해당 문장을 고치며 불필요한 문장은 덜어낸다. 괜찮은 문장까지 바꾸거나 검토 지적마다 주의 문단을 덧붙이지 않는다.

사실·수치·비교 조건을 근거와 대조하는 일과 문장이 자연스러운지 보는 일은 목적을 구분한다. 두 작업을 매번 별도 모델·필수 단계로 만들 필요는 없다. 중요한 불확실성과 필수 고지는 해당 정보 가까이에 짧게 쓰고, 작성자가 무엇을 검증·추정·제외했는지 같은 내부 검수 설명은 독자용 본문에 옮기지 않는다. 검수 보고 자체를 요청받았을 때는 그 결과가 본문이다.

분량·어미·문장 길이·질문형·강조·비유를 자연스러움의 공식으로 삼지 않는다. 불필요한 반복은 줄이되 필요한 설명까지 압축하지 않는다. 문단은 화제·설명의 역할이 바뀌는 곳에서 나누고, 짧은 호흡이 맞는 매체에서는 의미 단위 줄바꿈을 사용한다. 매 문장 강제 줄바꿈이나 어미 치환은 하지 않는다. 화면에 넣는 글은 실제 표시 폭에서 흐름·단계·수치와 단위가 흐트러지지 않는지 본다.

## 대안·모델 비교가 필요할 때만

기본안에서 이해가 계속 막히거나 사용자가 비교를 요청하면 같은 짧은 섹션의 대안을 먼저 본다. 실제 지원 모델·추론량은 당시 사용자 지시와 모델 라우팅을 따르고, 특정 모델이나 최고 추론량을 자연스러운 글의 보장으로 고정하지 않는다. 현재 owner의 설정을 임의로 바꾸지 않는다.

사실 오류와 중요한 설명 누락을 먼저 확인하고, 괜찮은 두 문안끼리 연결·이해·판단 가능성을 구체적인 문장으로 비교한다. 모델명·글의 길이·AI 탐지 점수·주관적인 총점만으로 선택하지 않는다. 원인을 알아보는 비교에서는 모델·입력·추론량·환경을 동시에 바꾸지 않는다. 명확한 차이가 없으면 동률로 두고 수정 부담이 적은 안을 고른다.

SEO·제목·출처·채널 서식은 자연스러운 본문을 작성한 뒤 필요한 범위에서 맞춘다. 별도 지시가 없으면 요청한 본문을 전달하고, 작성 과정이나 자체 평가를 덧붙이지 않는다.
